# Red Skill 发布操作说明

> 目标：把「开源项目选型助手」发布到小红书 Builder Hub。
> 全部素材已备好，你只需要按顺序点几下。

---

## 一、你要上传的东西

| 文件 | 用途 | 怎么用 |
|---|---|---|
| `content/xhs-skill.zip` | **主文件**，16.5 KB | 直接「选择 zip 文件」上传 |
| `content/xhs-skill/` | 上面那个 zip 解压后的同名文件夹 | 如果 zip 传不上，就选这个文件夹 |
| `content/skill-icon.png` | 图标，512×512（1:1） | 填写信息页如果要求图标就传 |
| `content/skill-cover.png` | 封面，1080×1440（3:4） | 同上 |

包里是 4 个文件（平台限制：单文件 ≤10MB、总计 ≤30MB，我们只有 16.5KB）：

```
xhs-skill/
  SKILL.md                     ← 主指令，3866 字节
  references/
    rubric.md                  ← 四个信号的判断阈值
    pitfalls.md                ← 14 类已知坑的识别特征
    catalog.md                 ← 172 个项目的中文目录
```

---

## 二、上传步骤（对应你截图的那两页）

### 第 1 步：上传源码

1. Builder Hub → **Red Skill** → 发布
2. 「选择上传方式」保持 **上传文件**
3. 点「**选择 zip 文件**」，选 `content/xhs-skill.zip`
   - 如果平台报错说格式不对，改用「选择文件夹」，选 `content/xhs-skill` 整个文件夹
4. 「**选择内容来源**」选 **Skill 源码为原创**
   - 这是我们自己写的，不是转载
5. 勾选「我已阅读并同意《Skill 发布安全规范》」
6. 点「**下一步**」

### 第 2 步：填写信息

**名称**（限制 14 字）

```
开源项目选型助手
```

**简介**（限制 14 字，推荐这两个之一）

```
判断开源项目值不值得用
```
```
三秒看出项目靠不靠谱
```

**场景标签**

优先选 **实用工具**；如果允许多选，再加 **学习知识**。

**图标 / 封面**

如果要图，用上面那张 `skill-icon.png`（1:1）和 `skill-cover.png`（3:4）。
两张图都**没有任何网址和二维码**，符合平台红线。

---

## 三、发布前必须知道的四条红线

这份 Skill 是按手册 §5.7 的教训写的，你也要守住：

1. **包里没有任何网址** —— 我已经用全文检索确认过，`SKILL.md` 和 3 个参考文件里
   没有一个 `http`、`github.io`、`www.`
2. **不要在小红书笔记正文里加链接**，也不要在评论区/置顶评论放
3. **不要写"去搜 XX""主页有链接"**，站名可以提，但不带"去搜"
4. 笔记要**自包含**：读者看完你这篇就够了，结尾只用"想看的可以关注我"

上面第 1 条是代码层面的保证，2~4 条要靠你发布时注意。

---

## 四、发完之后怎么用（关键一步）

Skill 发布审核通过后，它**不会自己带来流量**。要挂到笔记里：

1. 正常写一篇笔记（内容讲"我判断开源项目的方法"或某个具体项目的坑）
2. 发布时点「**组件**」→ 选择你发布的这个 Skill
3. 读者点组件 → 一键复制口令 → 装进自己的 Agent 里用

**第一次测试建议**：先发一条**仅自己可见**的笔记，挂上组件，用自己手机点一遍，
确认能正常复制口令。跑通了再发公开那条。

---

## 五、怎么验证它真的能用

Skill 里写了固定的输出格式，你可以这样测：

装进 Agent 后，输入任意一个仓库名，比如：

```
syncthing/syncthing
```

应该看到这样的结构：

```
【一句话结论】推荐用 / 可以用但有条件 / 不建议 / 情况不明
【四个信号】· 刷星风险 / 维护状态 / 维护压力 / 上手门槛
【适合谁】【不适合谁】
【最可能踩的坑】
【替代方案】
```

**如果它没按这个格式答**，说明 Skill 没被正确加载，回来告诉我，我调 SKILL.md。

再测一个"反向案例"，看它会不会正确地劝退：

```
Ebony-Vinyl/dsh-our-free-model
```

这个项目的特征是"免 API Key 用前沿模型 + 账号池"，应该被判为**高风险、不建议使用**。
如果它反而推荐了，说明坑库没生效，也要回来调。

## 六、以后怎么更新

项目库变了（比如又加了新项目），重新生成一次即可：

```powershell
python build_xhs_skill.py
```

它会重写 `catalog.md` 并重新打包 `xhs-skill.zip`，你重新上传覆盖就行。

---

## 七、预期，别抱太大希望

- **审核时间**：不确定，可能几小时到几天，新号可能更久
- **流量**：Skill 本身不带流量，**流量来自挂载它的那篇笔记**。所以还是得写内容
- **这东西的真实价值**：不是"多一个渠道"，而是把你的**判断方法**变成一个可以被安装、
  被传播的资产。别人转发你的笔记，转的是"方法"，不是"链接"

## 九、审核未通过怎么办（2026-11-21 首发被拒后补）

**现象**：1.0.0 版本显示「未通过」，但平台**没给理由**。

### 先找理由（三处都看）

1. 卡片上的「**版本历史**」→ 看有没有审核备注
2. 小红书 App / 网页的**站内信、通知中心**
3. 确认账号是否已完成**实名认证**（Red Skill 要求实名，未实名可能直接拒）

### 找不到理由时：一次只改一个变量

**第 1 次重传 → 用安全版 `xhs-skill-safe.zip`**

只改一件事：**去掉 `catalog.md`**。

为什么先怀疑它——那是唯一一处「非我方内容」：

- 172 条 `owner/repo` 项目标识（`microsoft/PowerToys` 这种写法）
- 含影视下载（yt-dlp、NewPipe）、电视去广告（cleanyourtv、aerial-tv）这类项目
- 平台对「外部平台信息」判定很严（手册 §5.7 有 11/15 被判违规的记录）

安全版里 SKILL.md 已有降级逻辑：没有 catalog 就不推荐具体项目名，改成给「该看哪几个维度」。

**第 2 次重传（如果安全版也被拒）→ 再摘 pitfalls 里的两段**

按顺序删这两条，一次删一条：

1. 第 8 条「影视资源 / 直播源聚合类」（提到磁力、IPTV）
2. 第 1 条「免登录免 API Key 用前沿大模型」（提到账号池）

这两段在内容审核眼里可能像"介绍违规服务"，虽然本意是提醒风险。

**第 3 次还不过 → 别再改了，去问**

重复提交失败版本可能影响账号信用。这时联系客服/私信官方，问具体拒绝原因。

### 不要做的事

- 不要一次改五处再传——过了也不知道是哪条起作用
- 不要为了过审删掉「风险提示」部分——那是这个 Skill 的核心价值
- 不要换个账号反复提交

## 八、如果卡住了

| 现象 | 大概率原因 | 怎么办 |
|---|---|---|
| 上传 zip 报错 | 平台只认文件夹 | 改「选择文件夹」 |
| 说 SKILL.md 缺失 | zip 多套了一层目录 | 我可以重新打一个不套目录的包 |
| 审核被拒，说含外部信息 | 包里有我没查到的链接 | 把拒绝理由截图给我，我改 |
| 审核通过但组件找不到 | 还没同步 | 等几小时再试 |
| 加载后格式不对 | frontmatter 字段不匹配 | 把实际报错给我，我调 |
