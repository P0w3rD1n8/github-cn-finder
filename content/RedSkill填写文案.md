在 GitHub 上看到一个项目，不知道能不能用、会不会踩坑？把仓库名丢给它，它按固定四步给你一句人话结论。

## 它会帮你判断什么

- 「这个项目靠谱吗 / 能用吗 / 有没有坑？」
- 「我想找一个做 XX 的开源软件，这个行不行？」
- 「这个 star 这么高，为什么你说是坑？」
- 「我要做 XX，有没有免费替代品？」

## 它的四步判断法

1. 看 fork 与 star 的比例 —— 正常 5%~10%；超过 30%、或 fork 比 star 还多，多半是刷的
2. 看最后一次提交 —— 超过一年没更新，基本可以当弃坑
3. 看未解决 issue —— 几千个积压只配几万 star，说明出了问题没人管
4. 看有没有安装包 —— 只有源码和 build from source 的，是给开发者用的

## 输出长什么样

【一句话结论】推荐用 / 可以用但有条件 / 不建议 / 情况不明
【四个信号】刷星风险 · 维护状态 · 维护压力 · 上手门槛
【适合谁】【不适合谁】
【最可能踩的坑】最多三条
【替代方案】同类项目推荐

## 它的态度

- star 高不等于好用，遇到高星项目先怀疑、再验证
- 分清「软件好不好」和「你适不适合用」——给开发者的命令行工具再优秀，普通人也不该硬上
- 涉及无障碍权限、USB 调试、Docker 部署这类操作，会明确提示风险
- 查不到的数据就说查不到，不编数字
