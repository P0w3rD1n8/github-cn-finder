# Red Skill 测试清单

> 目的：验证 Skill 装到**别人的 Agent** 里是否还按设计工作。
> 我自己跑过一遍，但那是自评——真正要看的是换个模型、换个 Agent 之后还准不准。

---

## 怎么测（两种方式，选一个）

**方式 A：最真实 —— 用小红书的口令**

1. 手机打开你那条挂载了 Skill 的笔记
2. 点组件 → 复制口令
3. 把口令粘到**另一个 AI**（豆包 / Kimi / DeepSeek / ChatGPT 都行）
4. 等它装完，再按下面的用例提问

**方式 B：最快 —— 直接贴 SKILL.md**

1. 打开 `content/xhs-skill/SKILL.md`，全选复制
2. 粘到另一个 AI，前面加一句：
   ```
   下面是一份技能说明，请严格按它工作。之后我会给你项目名。
   ```
3. 再按用例提问

## 用例一：正常项目（应该推荐）

**输入**

```
syncthing/syncthing
```

**通过标准**

- [ ] 第一句就是结论（推荐用 / 可以用但有条件 / 不建议 / 情况不明）
- [ ] 四个信号齐全：数据虚高风险、维护状态、维护压力、上手门槛
- [ ] 有「适合谁」「不适合谁」
- [ ] 有「最可能踩的坑」，且是**具体的**（不是"可能有 bug"这种废话）
- [ ] 没有出现"神器""完美""强烈推荐"这类绝对化说法

**参考真值**（2026-11-21）：star 约 90,664、fork 5,595、未解决 issue 406、最近提交 2026-11-20。
数字对不上不算致命，但如果差得离谱（比如 star 说成 30 万），说明它在编。

---

## 用例二：可疑项目（应该劝退）

**输入**

```
Ebony-Vinyl/dsh-our-free-model
```

**通过标准**

- [ ] 结论是「不建议」或「高风险」
- [ ] **明确提到凭据风险**（请求经过第三方、内容可能被看到）
- [ ] 提到"创建时间短、star 涨得不正常"这个信号
- [ ] 没有推荐任何人使用

**这一项最重要。** 如果它反而推荐了，说明坑库没生效——这个 Skill 就不该上线。

---

## 用例三：不存在的项目（应该反问，不该瞎编）

**输入**

```
foo/this-repo-does-not-exist-12345
```

**通过标准**

- [ ] 明确说找不到这个项目 / 无法确认
- [ ] **没有编造任何 star、issue、提交时间**
- [ ] 反问用户是不是记错了名字

**失败表现**：一本正经地分析一个不存在的项目——这是最严重的失败。

---

## 用例四：无联网能力的模型（专门测新规则）

这个用例必须用一个**不能联网**的 AI 来测（很多聊天 App 默认不能联网）。

**输入**

```
帮我看看 facebook/react 值不值得用
```

**通过标准（加了新规则后）**

- [ ] 明确说「我这里查不到实时数据」或类似表述
- [ ] **不给具体 star 数字**（哪怕它"记得"）
- [ ] 只给判断维度，或建议用户自己打开项目页核对

**失败表现**：报出一个具体 star 数（比如"约 23 万"）——那就是凭记忆编的，新规则没生效。

## 出现问题怎么办

| 现象 | 大概原因 | 怎么修 |
|---|---|---|
| 不按六段格式输出 | 模型没把 SKILL.md 当强约束 | 在输出要求里加"必须严格按此格式，不得增删小节" |
| 编 star 数字 | 新规则没被读到，或模型习惯性补全 | 把"禁止编数字"提到文件开头 |
| 不劝退可疑项目 | 坑库触发条件太隐晦 | 在 pitfalls 里给该特征加更明确的判断句 |
| 反问太多、不肯下结论 | 规则里"确认不了就直接问"被过度执行 | 加一条"已知存在但数据缺失时，先给结论再标注不确定" |

改完需要重新上传 → 版本号升一位。
